# AtomLearn 0.14.0 Release Notes

Status: superseded before publication. The signed `v0.14.0` tag workflow exposed a Python 3.10-only packaging bug after all tests passed, so it published no GitHub Release or stable assets. The tag remains unmoved for auditability; the corrected stable candidate is `v0.14.1`.

## Highlights

- Closed the non-Active Evidence state vulnerability and added Evidence v2 scorer, provenance, calibration, and eligibility controls.
- Added typed one-request start orchestration and shared layout-preserving Document IR for RAG, exams, and research.
- Added approved local learned embeddings, crash-safe HNSW generations, benchmark-gated reranking, and nonempty multilingual/multidomain retrieval gates.
- Added reviewed joint exam mappings, separate structural/official/empirical difficulty, reviewed item families, held-out memorization-risk reporting, and capacity-checked exam plans.
- Added protocol-bound literature discovery, DOI/title reconciliation, screening, citation expansion, integrity refresh, claim-level IR locators, structured facets, and reviewed cross-paper synthesis.
- Added qualified per-Atom memory with fixed, adaptive-shadow, and benchmark-plus-opt-in adaptive-active scheduling, plus a capacity-aware unified daily queue.

## Review scheduling contract

Fixed 1/3/7/30 scheduling remains the default and fallback. Only delayed, mastery-eligible A/B active-retrieval Evidence updates memory. Passive review, recognition, self-report, chat duration, satisfaction, and response speed alone cannot change stability, difficulty, retrievability, or due dates. Shadow mode never changes the actual queue. Active mode requires a current versioned benchmark and explicit learner opt-in, applies only to future schedules, and preserves existing pending and overdue history.

The bundled memory benchmark is an engineering invariant and calibration gate, not a learning-effect result. Workspace pilot reports are observational, cannot promote the adapter, and cannot support a causal benefit claim. Such a claim requires the separately consented study workflow with delayed and transfer outcomes.

## Schema and compatibility

Declared namespace schema versions remain at version 1. Existing v0.13 workspaces that lack Phase 7 review fields load with fixed defaults; historical review Evidence remains readable but does not become qualified adaptive history without an originally persisted active-retrieval observation. No existing pending review is rewritten during load or policy configuration.

Evidence v2 adds an optional strict `review_observation` object. Review policy has a published JSON Schema and template. The Release Manager capability smoke contract adds `review` and verifies the installed runtime's fixed default plus its current benchmark identity.

Core schemas, templates, benchmark profiles, and manifests are now explicit wheel package data resolved through one source/installed-runtime path boundary. The stable builder rejects review-capable runtime bundles whose Core wheel omits the scheduler or required review assets.

## Security and privacy

- Evidence still requires the canonical Active Atom and a qualified scorer before mastery.
- Review memory is reconstructed from persisted Evidence-linked events during validation; normalized fields and qualification reasons are re-derived from Evidence, so forged event flags, links, predictions, counts, states, or benchmark metrics fail closed.
- No raw response is added to review memory; the event stores scores, hint count, retrieval mode, delayed flag, scorer quality, and a coarse response-time bucket.
- No review policy, benchmark, queue, or pilot command uploads learning data.
- Installed runtime hashing permits only CPython venv's contained top-level `lib64 -> lib` alias, includes that alias in the digest, and rejects all other symlink/reparse entries.
- Cross-course personalization, strategy experiments, learning studies, Capsule export, and Release Manager actions retain their separate opt-ins and authority boundaries.

## Verification and release

The release gate covers the full test suite, Skill validation, schema and migration fixtures, release identity, manager upgrade and rollback, hostile archives, property tests, every-stage fault injection, privacy attacks, replay compatibility, and real installed-runtime capability smoke for Core, bridge, documents, RAG, exams, research, and review scheduling.

Stable publication remains tag-only and signature-required. `main` is a development source, not a stable update channel. Follow [Release Manager](../../atom-learn/references/RELEASE_MANAGER.md) and the [Operations and Recovery Runbook](../SELF_EVOLUTION_V2_OPERATIONS.md) for update, recovery, rollback, trust rotation, and release procedures.

## Known limits

- `atomlearn-memory-v1` is a deterministic DSR/FSRS-like Atom adapter, not a claim to implement or outperform a particular FSRS release.
- Local history does not train personalized parameters; verified defaults or fixed scheduling remain in use when evidence is insufficient.
- The unified queue is a daily capacity plan, not an optimizer that guarantees course completion.
- External/human scorer identity remains asserted provenance that Core cannot independently authenticate.
- Provider result limits and Document IR extraction quality still bound research, exam, and RAG completeness.
