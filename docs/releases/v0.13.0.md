# AtomLearn 0.13.0 Release Notes

Status: release-ready source. A stable release exists only after the signed `v0.13.0` tag workflow succeeds.

## Highlights

- Added strict Core version/schema compatibility manifests and deterministic migration planning.
- Added opt-in cross-course profiles with privacy-safe enum signals and explainable Effective Policy provenance.
- Added shadow-first, Evidence-linked teaching strategy experiments with conservative promotion and automatic pause.
- Added privacy-minimized local Evolution Capsules with attack-tested lint, preview, one-time export, maintainer deduplication, and reproduction-first conversion.
- Added an independent signed Release Manager with hostile-archive validation, copied-state migration, side-by-side installation, real Core health checks, atomic activation, stable dispatch, guarded recovery, and paired rollback.
- Added Phase 6 property, replay, backward-compatibility, migration, privacy, fault-injection, and cross-platform release gates.

## Schema and compatibility

All declared workspace, user, strategy, and Capsule schemas remain at version 1. No live-state transformation is required from the supported 0.11.0 or 0.12.0 Core paths. Update planning still copies and validates all selected state before activation and fails closed on undeclared, future, forbidden, or missing-migration state.

The Core manifest now publishes explicit default-off values for global personalization, strategy experiments, Capsule export, and the external Release Manager. Existing workspaces that have not opted in keep Core defaults and do not create or read global profile state.

## Security and privacy

- A non-Active or locked Atom cannot receive mastery Evidence.
- Personalization cannot weaken mastery, prerequisite, source-grounding, one-Active-Atom, or privacy invariants.
- Capsule lint blocks free text, content, local paths, URLs/DOIs, precise timestamps, identifiers, and samples smaller than the aggregation floor.
- Stable Core artifacts require an Ed25519-signed manifest, exact GitHub tag URL, matching package/Core/gate identity, and verified normalized content-tree hash.
- New Core code is never executed before verification.

## Update and rollback

Use `atomlearn-manager update check`, then review `update plan` before `update apply --confirmed`. Run the selected Core through `atomlearn-core`. If a process stops, run `update status` followed by `update recover`. Rollback accepts only the paired previous release and restores its matching pre-migration state when no later writes would be overwritten.

## Known limits

- The stable tag workflow requires repository signing secret/variable configuration and does not fall back to an unsigned release.
- There is no automatic telemetry or Capsule submission.
- Trust initialization, key rotation, stable tag creation, and manual-recovery decisions remain operator controlled.
- `main` is a development channel and is never a stable update source.
