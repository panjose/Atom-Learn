# AtomLearn 0.14.1 Release Notes

Status: superseded before publication. The signed `v0.14.1` tag passed the complete platform matrix but its final manifest build found that the release schema did not yet admit the newly required `review` smoke capability. It published no GitHub Release or stable assets. The tag remains unmoved for auditability; the corrected stable candidate is `v0.14.2`.

## Scope

AtomLearn 0.14.1 contains the complete 0.14 Phase 0–7 remediation: Evidence state safety, calibrated measurement, bounded self-evolution experiments, typed start orchestration, layout-preserving Document IR, semantic RAG, automatic exam and research workflows, qualified per-Atom adaptive review, and the unified daily queue. The full feature, compatibility, security, and limitation detail remains in the [0.14.0 feature notes](v0.14.0.md).

## Patch correction

The `v0.14.0` tag completed every test on Python 3.10–3.13, but its final runtime-wheelhouse step attempted to import `tomllib`, which exists only in Python 3.11 and later. Python 3.10 therefore produced no version argument and the fail-closed workflow published no Release or stable asset.

The tag remains unmoved. Version 0.14.1 reads the already installed Core distribution version through `importlib.metadata`, which is part of every supported Python version. A fast repository contract prevents regression to the Python 3.11-only import.

The `v0.14.1` attempt then correctly failed closed when its capability ledger required the new `review` runtime smoke but `release-manifest-v2.schema.json` still enumerated only the pre-Phase-7 capabilities. Version 0.14.2 aligns that schema with the ledger and adds a contract test requiring every ledger smoke capability to be schema-admissible.

## Release invariants

- Fixed 1/3/7/30 review scheduling remains the default and fallback.
- Adaptive-active review still requires a current benchmark and explicit learner opt-in.
- Self-evolution v2 capabilities retain their independent opt-ins and default-off boundaries.
- The stable release still requires the complete Windows/Linux Python 3.10–3.13 matrix, named HNSW gate, signed gate report, exact runtime matrix, Ed25519 signature, and immutable GitHub Release assets.
- The failed `v0.14.0` and `v0.14.1` attempts produced no stable manifest, Manager wheel, Core ZIP, runtime bundle, or GitHub Release.
