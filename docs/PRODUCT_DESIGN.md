## 1. 执行摘要

AtomLearn 不以“让 AI 一次讲完更多知识”为目标，而是把庞大的知识空间变成一条可控、可追踪、不会因追问而丢失主线的个性化学习路径。

系统先从一本或多本教材中抽取概念、技能与先修关系，将它们组织成知识 DAG（有向无环图），再拆成可在一次连续教学对话中完成的 Knowledge Atom。任一时刻最多只有一个 Active Atom；学习者可以围绕它无限追问，但只有在产生可验证的掌握证据后，系统才允许推进。

AtomLearn 的本质是三个系统的组合：

1. 基于用户资料的知识建模系统；
2. 有状态、受约束的对话式教学系统；
3. 可审计、可恢复、支持间隔复习的学习进度系统。

## 2. 问题定义

常规 AI 教学容易出现四类问题：

- 回答一次覆盖多个概念，学习者每个概念都只获得浅层理解；
- 追问引出更多分支，原来的学习位置和目标逐渐丢失；
- “我懂了”被当作掌握证据，缺少主动回忆与迁移验证；
- 长对话或跨会话后，AI 无法可靠恢复学习进度、误区与未解决问题。

AtomLearn 要解决的是学习控制问题，而不仅是内容生成问题。

## 3. 产品目标与非目标

### 3.1 目标

- 将一本或多本资料重组为独立于教材目录的知识 DAG；
- 将知识拆成粒度适当、目标明确、可验证的 Knowledge Atoms；
- 始终维持唯一 Active Atom，并可跨会话精确恢复；
- 对问题进行当前问题、阻塞问题和非阻塞问题分流；
- 用实际表现而非自我声明判断掌握状态；
- 记录来源、证据、误区、尝试次数与复习计划；
- 根据学习者表现动态拆分或合并 Atom；
- 让所有关键状态对人类可读、可检查、可版本化。

### 3.2 MVP 非目标

- 不构建通用知识图谱数据库或多人在线学习平台；
- 不自动抓取受版权保护的完整教材；
- 不承诺对所有学科完全自动且零人工校正地建图；
- 不以考试题库、排行榜、社交或游戏化为首要功能；
- 不在 MVP 中实现复杂的机器学习推荐模型；
- 不用华丽 UI 替代状态正确性与教学协议。

## 4. 核心不变量

以下规则属于系统约束，而不是可选的表达风格：

1. **单一焦点**：任一课程工作区最多只有一个 Active Atom。
2. **先修守卫**：先修未满足的 Atom 不得被激活。
3. **证据驱动**：仅凭“懂了”不能进入 mastered。
4. **主线不丢失**：任何追问都不能隐式改变 Active Atom。
5. **可恢复**：每次状态变更后，重新打开工作区都能恢复当前目标、上下文和下一动作。
6. **来源可追踪**：资料驱动的知识与结论必须能回溯到来源位置。
7. **稳定标识**：Atom 标题和顺序可以变化，ID 一旦被进度引用就保持稳定。
8. **确定性变更**：AI 做判断，脚本验证并提交状态变更；非法转换必须失败且不留下半更新状态。

## 5. 典型用户旅程

### 5.1 新建课程

用户提供目标、已有基础、时间约束和一本或多本资料。AtomLearn 完成资料清点、概念抽取、冲突标记、依赖建图、原子化和入口诊断，展示地图摘要及第一个可学习 Atom，但不立即进行长篇授课。

### 5.2 围绕当前 Atom 深入学习

系统按 Why → What → How → Example → Intuition 组织教学。学习者可连续追问；回答必须说明追问与当前 Atom 的关系，且不得顺带推进后续 Atom。

### 5.3 处理旁支问题

- 当前 Atom 内的问题：直接回答并维持当前状态；
- 阻塞性先修问题：暂停当前 Atom，创建临时回溯栈，补齐先修后返回；
- 非阻塞问题：写入 Parking Lot，继续主线；
- 属于后续 Atom 的问题：记录到对应 Atom，不提前授课。

### 5.4 验证与推进

系统选择与目标匹配的小型检查，例如复述、计算、辨错或迁移。只有达到掌握阈值后，才记录证据、更新进度、解锁依赖节点并选择下一个 Atom。

### 5.5 跨会话恢复与复习

新会话优先读取当前状态和到期复习项，简要复述“正在学什么、哪里卡住、下一步做什么”。到期复习失败时降低置信度并重新激活针对性练习，不直接抹除历史掌握记录。

## 6. 领域模型

| 对象 | 作用 | 关键字段 |
| --- | --- | --- |
| Course | 一次完整学习计划 | `id`、目标、学习者画像、策略、状态 |
| Source | 用户提供的教材或知识来源 | `id`、类型、路径/URL、版本、定位规则 |
| Atom | 最小可学习与可验证单元 | `id`、目标、先修、难度、来源、掌握规则 |
| Dependency | Atom 间的有向关系 | `from`、`to`、关系类型、理由 |
| Session | 当前教学焦点与会话模式 | Active Atom、阶段、问题、下一动作、回溯栈 |
| Question | 学习者提出或系统发现的问题 | 文本、归属、类型、优先级、状态 |
| Evidence | 一次掌握判断的原始证据 | 题目、回答摘要、量规结果、时间、评语 |
| Review | 间隔复习任务 | Atom、到期时间、间隔、结果 |
| Event | 可审计的状态变更记录 | 事件类型、时间、前后状态、原因 |

### 6.1 Knowledge Atom 的边界

一个 Atom 应同时满足：

- 只有一个可陈述的核心学习目标；
- 可在一次连续教学对话中解释、讨论、练习和验证；
- 能设计至少一项有效的掌握检查；
- 先修关系可明确列举；
- 过大时可拆成仍然有意义的子 Atom，过碎时可合并而不引入第二个独立目标。

经验上，一个 Atom 包含一个核心概念或机制、一个代表性示例、常见误区以及一组轻量验证。`导数`过大，`符号 f`过小，`导数的形式化定义`通常是合适粒度。

### 6.2 Atom 建议结构

```yaml
schema_version: 1
id: calculus.derivative.definition
title: 导数的形式化定义
objective: 能解释并使用差商极限定义导数
prerequisites:
  - calculus.function.basics
  - calculus.limit.intuition
difficulty: 2
estimated_minutes: 25
status: available
sources:
  - source_id: textbook-a
    locator: Chapter 3, Section 3.1, pp. 72-76
misconceptions:
  - 可以直接令 delta_x 等于 0
mastery:
  required_dimensions: [explain, apply, discriminate]
  pass_threshold: 0.8
```

## 7. 状态模型

原始构想中的 `QUESTIONING`、`CHECKING` 更接近会话阶段，而 `LOCKED`、`MASTERED` 更接近 Atom 生命周期。将二者拆开可避免一个字段同时表达两种含义。

### 7.1 Atom 生命周期

```text
locked ──先修满足──> available ──激活──> active
  ^                                   │
  │                                   ├──检查未通过──> active
  │                                   │
  │                                   └──检查通过──> mastered
  │                                                     │
  │                                         复习到期──> review_due
  │                                                     │
  └────────────图重构且先修不再满足─────────────────────┘
```

`mastered` 表示已通过当前掌握门槛，并非永久不会遗忘。课程层面的 `completed` 由必修 Atom 全部掌握且无阻塞任务来决定，不作为普通 Atom 的重复状态。

### 7.2 Session 阶段

```text
orientation → teaching ↔ questioning → checking
                    ↑          │           │
                    └──────────┴──未通过───┘
                                           │通过
                                           ↓
                                      transitioning
```

另有 `reviewing`、`paused` 和 `blocked` 三种可恢复模式。Session 阶段变化不得暗中改变 Atom 生命周期。

### 7.3 激活守卫

激活 Atom 前必须验证：

- 目标 Atom 存在且不是 archived；
- 所有必需先修均已 mastered，或存在有理由且被显式记录的豁免；
- 当前没有另一个 Active Atom；
- 若从阻塞回溯返回，回溯栈顶与目标一致；
- 状态文件通过 schema 和 DAG 校验。

## 8. 学习协议

### Phase 0：Orientation

1. 登记课程目标、用户基础与学习约束；
2. 清点并解析来源；
3. 抽取候选概念、技能、关系与来源定位；
4. 去重、处理术语别名并标记来源冲突；
5. 构建并验证 DAG；
6. 拆分 Atom 并为每个 Atom定义掌握标准；
7. 通过诊断或用户确认标记已有掌握；
8. 选择第一个可学习 Atom，生成可读地图。

### Phase 1：Teach

教学只围绕 Active Atom，默认采用：

1. Why：它解决什么问题；
2. What：概念或机制是什么；
3. How：如何推导、使用或执行；
4. Example：一个最小但有代表性的例子；
5. Intuition：用学习者已有知识建立直觉连接。

教学响应应短到足以给学习者留出思考与追问空间。是否进入检查由内容覆盖和互动证据共同决定，不由回答轮数决定。

### Phase 2：Questioning

每个问题先路由再回答：

| 类型 | 判定 | 动作 |
| --- | --- | --- |
| `in_atom` | 属于当前目标或误区 | 立即回答，保持 Active Atom |
| `blocking_prerequisite` | 不解决就无法理解当前 Atom | 暂停并激活补救 Atom，压入回溯栈 |
| `non_blocking` | 有价值但不影响当前目标 | 记录到 Parking Lot，简短确认后返回主线 |
| `future_atom` | 已有后续 Atom 覆盖 | 关联到该 Atom，不提前展开教学 |
| `out_of_scope` | 与课程目标无直接关系 | 记录或明确拒绝扩展范围 |

问题分类可能由 AI 判断，但所有状态动作必须通过确定性脚本提交。

### Phase 3：Mastery Check

掌握检查按 Atom 目标从以下维度选择至少两项；纯事实型 Atom 可按量规减少，但必须说明原因：

- `explain`：用自己的话复述核心机制；
- `apply`：在典型情境中使用；
- `discriminate`：识别反例、边界或常见误区；
- `transfer`：迁移到轻微变化的新情境；
- `teach_back`：向一个假想初学者讲解。

检查结果为 `mastered`、`partial` 或 `not_mastered`。必须保存题目、回答摘要、各维度评分和反馈理由。`partial` 与 `not_mastered` 回到针对性教学，不推进。

### Phase 4：Advance / Review

通过检查后：

1. 写入 Evidence；
2. 更新置信度、尝试次数和最后复习时间；
3. 安排默认 1、3、7、30 天的复习，可由课程策略覆盖；
4. 重新计算可用节点；
5. 生成进度视图；
6. 只展示少量候选下一步，并按关键路径、学习目标和认知负荷选择。

## 9. 多来源知识建模

教材是 Source，知识体系才是主结构。Orientation 不按资料分别复制目录，而是把多来源内容映射到共享 Atom。

每个来源定位至少包含 `source_id` 和稳定 locator；有页码时记录页码，有章节或锚点时同时记录。不同来源有冲突时：

1. 保留各自观点和定位；
2. 标记冲突类型（术语、定义域、符号、结论或教学顺序）；
3. 优先使用课程指定的权威来源；
4. 没有权威优先级时向用户呈现差异，不静默合并；
5. 生成内容不得伪装为来源原文。

## 10. 动态原子重构

Atom 初始地图是可修订假设，不是固定目录。

### 10.1 拆分触发条件

- 连续两次针对不同子目标检查失败；
- 教学或答疑长期同时涉及多个独立机制；
- 单个 Atom 预计学习时间明显超过课程上限；
- 一个先修缺口只影响 Atom 的部分内容。

拆分时保留父 ID 作为容器或 archived alias，新子 Atom 使用稳定后缀并迁移来源、问题和证据，不丢历史。

### 10.2 合并触发条件

- 两个 Atom 总是一起教学和验证；
- 其中一个无法设计独立掌握检查；
- 学习者的已有基础使拆分产生无意义摩擦。

合并必须保留旧 ID 到新 ID 的 alias，重新验证 DAG，并记录结构变更事件。MVP 由 AI 提议、用户确认后执行；后续版本再考虑自动执行。

## 11. 持久化架构

### 11.1 Skill 本体与学习数据分离

Skill 是可复用、可更新的程序包；课程状态是用户数据。二者不能放在同一个可安装目录中，否则升级 Skill 可能污染或覆盖学习记录。

```text
repository/
├── atom-learn/                 # 可安装 Skill，保持精简
│   ├── SKILL.md
│   ├── agents/openai.yaml
│   ├── scripts/
│   ├── references/
│   └── assets/templates/
├── docs/                       # 项目设计与实施文档
├── examples/                   # 可公开的示例课程
└── tests/                      # 状态机与端到端测试

user-course-workspace/
├── .atomlearn/                 # 规范化、机器可校验的事实来源
│   ├── course.yaml
│   ├── graph.yaml
│   ├── atoms/
│   ├── state/current.yaml
│   ├── questions.yaml
│   ├── reviews.yaml
│   └── events.ndjson
├── LEARNING_MAP.md             # 生成的人类可读视图
├── CURRENT.md
├── PROGRESS.md
├── QUESTIONS.md
└── SOURCES.md
```

### 11.2 单一事实来源

`.atomlearn/` 中的 YAML/NDJSON 是规范状态；根目录 Markdown 是由脚本生成的可读投影。用户可以审阅 Markdown，但任何可影响状态机的修改都必须进入结构化状态并通过验证，避免同一状态在多个 Markdown 文件中漂移。

### 11.3 当前状态示例

```yaml
schema_version: 1
course_id: calculus
active_atom_id: calculus.derivative.definition
phase: questioning
current_question: 为什么 delta_x 不能直接等于 0？
learner_understands:
  - average-rate-of-change
  - limit-intuition
learner_confusions:
  - approaching-zero-vs-equal-zero
next_action: explain-difference-quotient-limit
backtrack_stack: []
updated_at: 2026-08-13T10:00:00+08:00
```

### 11.4 一致性与恢复

- 所有写操作先写临时文件、校验完整工作区后再原子替换；
- 每次成功变化追加 Event，包含原因与关联 Evidence；
- 脚本拒绝环、悬空依赖、未知状态、重复 Active Atom 和失效引用；
- Markdown 投影包含生成时间与状态摘要，但不包含唯一存在于投影中的事实；
- `validate` 与 `render` 可重复执行，重复运行不产生语义变化。

## 12. Skill 组成与职责

`SKILL.md` 只保留核心流程、工具调用顺序、状态守卫和引用路由，详细 schema、原子化规则、问题路由量规和掌握量规放在 `references/`，以控制上下文体积。

确定性脚本负责：

- 初始化课程工作区；
- 校验 schema、DAG 和状态不变量；
- 激活/暂停/恢复 Atom；
- 记录问题与 Evidence；
- 应用合法状态转换；
- 计算解锁节点和复习日期；
- 渲染 Markdown 视图。

AI 负责语义任务：资料理解、概念抽取、关系建议、教学表达、问题分类建议、答案评估和动态重构建议。脚本不假装解决这些开放式判断。

## 13. 响应契约

每次教学回复在内部遵循以下顺序：

1. 读取并确认课程及 Active Atom；
2. 判断用户输入属于回答、追问、状态命令还是范围变更；
3. 如是问题，先分类并决定状态动作；
4. 只生成当前必要的解释或检查；
5. 将问题、误区、证据和下一动作写入状态；
6. 校验并渲染视图；
7. 用简短文本告诉用户当前发生了什么。

禁止行为包括：一次讲完整章、因追问顺带介绍多个后续概念、无证据标记掌握、静默更换 Active Atom、仅在对话上下文中保存关键进度、伪造来源定位。

## 14. 可观测性与成功指标

### 14.1 状态正确性

- 100% 的提交后工作区满足单 Active Atom 和 DAG 不变量；
- 100% 的 mastered 转换存在 Evidence；
- 100% 的资料性 Atom 至少有一个有效来源定位或显式标记为 AI 补充；
- 崩溃或跨会话后可从磁盘恢复，无需依赖聊天历史。

### 14.2 学习体验

- 用户追问五轮后仍能准确指出当前 Atom 与下一动作；
- 非阻塞旁支问题被记录但不打断主线；
- 用户能从 `CURRENT.md` 在一分钟内理解当前状态；
- 掌握后复习的正确率和保持率可追踪。

### 14.3 质量指标

- Atom 粒度调整率：过高说明初始原子化不稳定，过低可能说明系统没有适应学习者；
- 检查首过率、平均尝试次数、回溯次数、到期复习完成率；
- 状态校验失败率和来源定位缺失率；
- 用户主动纠正地图与来源冲突的比例。

## 15. 风险与设计对策

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| AI 生成错误依赖 | 学习路径不合理或形成环 | DAG 校验、来源依据、用户可审阅、结构事件记录 |
| Atom 粒度失衡 | 认知负担过大或流程琐碎 | 粒度量规、动态拆并、统计尝试与时长 |
| 自信评分虚假精确 | 误判掌握 | 保存分维度 Evidence，不把单个浮点数当真相 |
| Markdown 与状态漂移 | 恢复错误 | 结构化状态为事实来源，Markdown 只生成 |
| 追问分类错误 | 错误回溯或主线中断 | 分类理由可见、动作可撤回、关键重构需确认 |
| 来源幻觉 | 无法核验知识 | 强制 source locator；不确定时明确标记 |
| 教材隐私或版权泄露 | 数据与合规风险 | 默认本地处理、最少引用、禁止提交私有教材到仓库 |
| Skill 升级覆盖课程 | 学习记录丢失 | 安装目录与学习工作区分离、schema 迁移与备份 |

## 16. MVP 验收边界

MVP 只要可靠完成以下闭环即算成功：

1. 从一个主题和至少一份来源建立小型 DAG；
2. 生成 10–30 个带来源和掌握规则的 Atom；
3. 激活唯一 Atom 并进行教学、追问、问题分流；
4. 完成一次失败检查、补救教学和通过检查；
5. 记录 Evidence，解锁后继并生成复习项；
6. 关闭会话后仅凭工作区恢复；
7. 所有状态通过自动校验，Markdown 视图与规范状态一致。

超出该闭环的自动大规模建图、可视化 UI、云同步与个性化推荐均留到后续版本。

## 17. 已确定的关键决策

- 产品名采用 **AtomLearn**，Skill 目录名采用 `atom-learn`；
- 底层使用 DAG，而不是简单目录树；
- 同时区分 Atom 生命周期与 Session 阶段；
- 结构化文件是状态事实来源，Markdown 是人类可读投影；
- Skill 本体与用户课程数据分离；
- AI 做语义判断，确定性脚本守护状态转换；
- MVP 中动态拆分/合并必须由用户确认；
- 先完成文件优先的可靠闭环，再考虑 UI 或数据库。

## 18. 待验证问题

- 默认的 Atom 粒度在数学、编程、语言和人文学科之间是否需要不同量规；
- 无现成标准答案时，mastery rubric 如何减少 AI 自评偏差；
- 多来源冲突的默认权威优先级应由用户、课程配置还是来源类型决定；
- 大型课程的 Orientation 是否需要分批建图并允许边学边扩展；
- 固定复习间隔与 SM-2 类自适应算法在真实使用中的收益差异。
